# LNH-MusicTag 副本目录整理 · 处理过程记录

> 整理对象：`E:\mp3 - 副本 - 副本 (2)`、`E:\mp3 - 副本 - 副本 (3)`
> 目标：将副本目录扫描入库 → 去重复 → 一键刮削补全标签，整理为独立可用的音乐库，不破坏其他文件夹。
> 日期：2026-10-11 ~ 2026-10-12

---

## 1. 处理流程总览

```
登录鉴权 → 扫描目录 → 轮询扫描进度 → 拉取曲目清单
        → 去重（分组计算 → 删除多余文件）
        → 一键刮削（乱码修复 → 繁转简 → 补艺术家 → 多源刮削）
        → 人工修正（Unknown 文件重命名 / 乱码标签修复）
        → 结果核验
```

每个环节都有对应的 HTTP 接口与后端技术支撑，下文按步骤记录"做了什么、用了什么接口、什么技术"。

---

## 2. 逐步骤明细

### 2.1 会话登录
- **做了什么**：向服务端验证 admin 账号，换取登录会话。
- **接口**：`POST /api/login`（body: `{"user":"admin","pass":"admin"}`）
- **技术**：
  - 服务端校验 bcrypt 密码哈希，签发签名 Cookie（HttpOnly + SameSite）。
  - 会话密钥 `session_secret` 首次启动随机生成，存 SQLite。
  - 后续所有请求携带该 Cookie，并带自定义头 `X-Requested-With: LNH-MusicTag` 通过 CSRF 校验。

### 2.2 扫描目录
- **做了什么**：将 `E:\mp3 - 副本 - 副本 (2)` / `(3)` 的全部音频文件扫描入库。
- **接口**：`POST /api/scan`（body: `{"dir":"E:\\mp3 - 副本 - 副本 (3)"}`，中文路径需 UTF-8 编码 + 转义反斜杠）
- **技术（扫描器）**：
  - 遍历目录，按扩展名白名单收集音频：`.mp3 .flac .m4a .aac .wav .ogg .opus .wma .ape .wv .aiff .dsf .dff` 等。
  - 逐文件执行：
    - **标签读取**：go-taglib（TagLib 的 WASM 封装，免 CGo）读取标题/艺术家/专辑/歌词等。
    - **格式探测**：时长、码率、采样率、声道。
    - **内容哈希**：计算 SHA256，用于内容级去重。
    - **标记检测**：乱码标记（GBK/UTF-8 错读检测）、繁体标记（OpenCC 检测）、待识别标记（无文件名与标签信息）。
    - **文件名解析**：`艺术家 - 歌名.后缀` 拆分；多后缀文件（如 `.mp3.flac`）按真实格式探测。
  - **异步增量扫描**：扫描不阻塞页面，边扫边入库，前端轮询进度。
- **进度查询**：`GET /api/scan/status`（返回 running / done / total / added）。

### 2.3 去重（核心步骤）
- **做了什么**：
  - **副本 (2)**：对比库内全部曲目，发现 570 首与原始库 `E:\mp3` 内容完全相同 → 删除副本保留原件，副本目录剩 18 首独有。
  - **副本 (3)**：仅在本目录内部对比（不跨文件夹），发现 34 组重复 → 删除 35 个多余文件（同曲双格式/多拷贝），剩 553 首。
- **接口**：
  - `GET /api/duplicates`（返回分组列表：`{key, method, count, ids}`）
  - `POST /api/duplicates/remove`（body: `{"ids":[...]}`，按 id 删除磁盘文件并同步移除列表）
- **技术（去重算法）**：
  - **三种分组口径**：
    1. **内容哈希（hash）**：SHA256 完全一致 = 同一份文件拷贝。
    2. **艺术家 + 标题（artisttitle）**：标签或文件名解析出的"歌手-歌名"一致（同人同歌，可能不同版本/格式）。
    3. **同名多格式（samename）**：文件名（去后缀）相同。
  - **保留规则（keep）**：每组保留音质最好的一首——**无损格式（flac/wav/alac 等）优先于有损（mp3/aac 等），同格式保留先扫描的一首**。
  - **keep 并集保护**：同一曲目若同时出现在多个分组，只要在任一组是保留者，就不会被其他组删除（防误删）。
  - **范围控制**：副本 (3) 的去重只取该目录内文件参与分组，不与其他目录比对，确保 E:\mp3 / 副本(2) 零改动。

### 2.4 一键刮削（批量整理）
- **做了什么**：对剩余曲目按"修复 → 转换 → 补全 → 刮削"流水线整理。
- **接口**：
  - `POST /api/scrape/onekey`（body: `{"ids":[...], "dedup":false}`，返回 `{jobId}`）
  - `GET /api/jobs/{id}`（轮询任务进度：status / done / total / stage / stageLabel / results）
- **技术（一键刮削流水线，pipeline.go）**：
  - **阶段 1 · 乱码修复**：GBK/UTF-8 错读检测（mojibake），识别后重写为正确编码；修复结果统一转简体。
  - **阶段 2 · 繁体转简体**：OpenCC（zhscript 封装）`t2s` 转换标签文本。
  - **阶段 3 · 文件名补艺术家**：文件名不含真实艺术家时，从文件名/标签补全。
  - **阶段 4 · 多源刮削**：按 `auto` 自动语言优选（中文→国内源，外文→国际源），逐曲目刮削歌名/艺术家/专辑/海报/歌词；当前源没搜到海报时自动匹配下一条源。
  - **刮削源**（插件化，可开关）：网易云 / QQ音乐 / 酷狗 / 酷我 / 咪咕 / B站 / 汽水 / 波点 / 5sing / MusicBrainz / iTunes / ListenBrainz / Deezer / Last.fm / Spotify / Discogs / Jamendo。
  - **写入方式**：go-taglib 写标签（标题/艺术家/专辑/日期/流派），海报写入内嵌封面（APIC），歌词写入标签（USLT）。
  - **任务引擎**：后台异步执行，逐曲目 × 阶段计进度，成功/失败/跳过统计；`POST /api/jobs/{id}/cancel` 可随时取消。

### 2.5 人工修正与重命名
- **做了什么**：
  - 副本 (2)：修正 1 首——`泠鸢yousa` 的艺术家标签乱码（娉犻涪yousa）+ 刮削错配歌名，改回 `泠鸢yousa - 外婆桥.flac`。
  - 副本 (3)：10 首文件名仍为 `Unknown - xxx` 但标签已正确 → 按标签重命名为 `真实艺术家 - 歌名.后缀`。
- **接口**：`POST /api/tracks/{id}/tags`（body: `{"tags":{"TITLE":"...","ARTIST":"..."}}`，注意必须用大写键名才会触发重命名）
- **技术**：写标签后若标题/艺术家与文件名不符，自动按「艺术家 - 标题.后缀」重命名；目标文件名已存在时自动加序号避免覆盖。

### 2.6 结果核验
- **做了什么**：重新拉取曲目清单，逐项检查标题、艺术家、海报、外挂歌词、Unknown 残留、总体积。
- **接口**：`GET /api/tracks`（返回全部曲目及 tags / hasCover / hasLrcFile / size 等）

## 5. 关键技术一览

| 技术 | 用在哪里 |
|------|----------|
| go-taglib（WASM TagLib，无 CGo） | 标签读写、封面/歌词写入 |
| SHA256 | 内容级去重 |
| OpenCC（zhscript） | 繁体检测与简体转换 |
| GBK/UTF-8 mojibake 检测 | 乱码修复 |
| 多源刮削调度（语言优选 + 源回退） | 一键刮削阶段 4 |
| 音质优先 keep 算法（无损>有损） | 去重保留决策 |
| Cookie 会话 + CSRF 头 | 全部接口鉴权 |
| 异步任务引擎（进度/取消/统计） | 扫描与批量任务 |
