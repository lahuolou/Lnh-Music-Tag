# 发展路线

已完成项见 [CHANGELOG](../CHANGELOG.md)（插件原子升级、四协议网关、SQLite 并发、实体/歌词缓存、移动端卡片、品质分级、后台监控刮削、按专辑/歌手名整理等均已落地）。以下为剩余规划。

## 安全与数据保护

- 插件包增加 SHA-256 校验清单/签名机制；插件进程隔离和权限声明作为后续安全边界建设。
- 持续审查管理 API 的认证、CSRF、路径权限、危险操作和审计日志；禁止状态变更走 GET。

## 协议兼容

- 维护 Subsonic/OpenSubsonic、Navidrome、Jellyfin、Emby 四份接口清单和独立测试。
- 每次发布至少跑音流/Musiver、Symfonium、Ultrasonic、Subtracks 等真实客户端；记录版本和复现步骤，避免"理论兼容"冒充实测（已完成：音流、StreamMusic、Subtracks、DSub、Ultrasonic、Findroid、Jellyfin 官方）。

## 性能与可靠性

- 建立 1 万、5 万、10 万曲目基准；测扫描时间、列表响应、内存峰值、SQLite 查询和封面并发（已有 1 万曲目基准基线）。
- 转码限制并发和线程，客户端断开时取消子进程；记录转码耗时、失败率和残留进程。

## 移动端体验

- 对小屏、横屏、系统安全区、软键盘、键盘/屏幕阅读器进行自动化与人工验收。
- 将桌面表格与手机卡片的交互状态统一，确保筛选、排序、选择和懒加载行为一致。

## 插件生态

- API v1 固化契约；未来重大变化引入 v2 并提供迁移期。
- 插件清单增加最低宿主版本、权限、依赖、哈希、签名和健康检查。
- 建立插件 SDK、示例仓库、兼容性测试套件和 CI 打包模板。

## 发布门槛

发布前必须通过 Go tests、race detector、go vet、Go build、前端 production build、四协议冒烟测试、插件升级/回滚测试和移动端验收。未执行的测试应显式标注，不能用静态检查替代实测。
